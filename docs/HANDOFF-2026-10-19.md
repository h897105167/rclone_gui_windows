## 二、本轮修复（全部有实测证据）

| 缺陷 | 根因 | 影响 |
|---|---|---|
| 远程列表只渲染第一行 | `Card` 对齐是 `start`，列表容器只写 `vertical-stretch: 1` 拿不到剩余空间 | 4 条远程只看到 1 条，且滚不动 |
| 启动时代理配置表为空 | 初始加载序列没有 `ProxyListRefresh` | 远程行显示代理名、卡片却是「代理配置（0）」 |
| 确认弹窗在窗口底部被裁 | `pop-ay` 只按行位置算；`root.height` 是滚动内容高度不是可视高度 | 确认/取消按钮跑到窗口外 |
| **删除代理后不回滚 rclone** | 先 `save_from_cfg` 删绑定，回滚时已读不到 `original_override`，被判定「不归本程序管」 | `rclone.conf` 永久留着已删除的代理地址 |
| ftp/sftp 代理静默无效 | 只写 `override.http_proxy`，这两类后端不读该键 | 用户以为走代理，实际直连 |

## 三、关键结论

- **ftp / sftp 只认原生键**：`http_proxy = <完整URL>`、`socks_proxy = <裸 host:port>`
  （带 `socks5://` 会 `too many colons in address`）。现在分配代理时会明确提示无效，
  真正支持需要按类型选键并同步改回滚/冲突检测/reconcile。
- **代理失败文案**已做归因：只在原文有 `proxyconnect` / 407 / 502 时翻译，其余原样透出。
  原始样本见 `docs/proxy-ftp-sftp-and-errors.md`。
- **UI 自动化三根因**：DPI 未感知、双屏虚拟桌面原点为负、前台锁。做法见
  `docs/ui-interaction-verification.md`，脚本在仓库外 `ui_probe/`。

## 四、建议的下一步

1. 把 ftp / sftp 的原生键支持做完整（键表已给，注意回滚要能记住用的是哪个键）。
2. 代理配置的「删除确认」目前是页面内联块、位置偏低，建议改成锚定弹窗。
3. 插件页同样补一次手工过审：本轮只覆盖了仪表盘/文件/远程/挂载/服务/传输/设置的主路径。
4. 清理 plugin 测试里的 4 条 `unused_mut` 警告，恢复「0 警告」基线。
