## 一、UI 交互终于可以自动化验证

上一轮结论是「本机 Slint 内容区点击送不进去」。实测推翻：不是 Slint，而是三个外部原因：

| 根因 | 实测现象 |
|---|---|
| 进程 DPI 未感知（175%） | 3840×2160 屏被当作 2194×1234，坐标整体错位 |
| 双屏虚拟桌面原点为负 `(-1440,-402)` | 目标 `(189,220)` 落到另一屏的 `(-1181,-141)` |
| 前台锁 | `SetForegroundWindow` 被拒，输入打给别的窗口（曾误点成最大化） |

做法：`SetThreadDpiAwarenessContext(-4)` → 虚拟桌面归一化或 `SetCursorPos` → 按 Alt + `AttachThreadInput` 置前 → **发送输入前断言前台**。脚本在仓库外 `ui_probe/`，方法沉淀在 `docs/ui-interaction-verification.md` 与 Obsidian `Agent_Input_Windows_Desktop.md`。

验证通过项：导航切换、连接/握手（真实 401→Basic 链路）、远程页代理列下拉（rclone 侧真写入 `override.http_proxy`）、删除确认框（取消不删/确认真删）、底部状态栏三项跳转、错误面板关闭与清空、历史记录清空、托盘单击无动作 / 真实双击唤起 / 右键原生菜单 / 菜单唤起、新建代理表单含校验。

## 二、ftp / sftp 代理穿透：结论是「当前实现无效」

用 `rclone serve ftp|sftp` 作目标 + 会真转发的 SOCKS5/HTTP CONNECT 见证器：

| | 直连 | SOCKS5 | HTTP 代理 |
|---|---|---|---|
| ftp | ✅ | ✅（控制 + 被动数据连接都过代理） | ✅ |
| sftp | ✅ | ✅ | ✅ |

但 **`override.http_proxy`（RCGUI 唯一写的键）对 ftp/sftp 完全不生效** —— 列表成功、代理侧零连接，属静默直连。它们只认原生 `http_proxy`（完整 URL）/ `socks_proxy`（**必须裸 `host:port`**，带 `socks5://` 会 `too many colons`）。现已在 UI 明示「不会真正生效」，不再谎报。详见 `docs/proxy-ftp-sftp-and-errors.md`。

## 三、代理失败的错误文案

采样 7 类真实失败原文（拒绝 / DNS / 407 / 502 / 超时 / TLS 不匹配 / EOF），实现只在原文有明确代理证据时翻译成可操作提示，并保留 rclone 原文；超时与 EOF 对「远端不可达」同样成立，只做弱提示；目标站点自身拒绝连接则原样透出（单测锁定）。

界面实测输出：

```
【代理】代理拒绝连接：代理端口上没有服务在监听：请确认代理软件已启动，并核对代理配置里的地址与端口。
（rclone 原文：… proxyconnect tcp: dial tcp 127.0.0.1:9: … actively refused it.）
```

## 四、修掉的 6 个缺陷

| # | 缺陷 | 根因 |
|---|---|---|
| 1 | 远程列表只渲染第一行（4 条只看到 1 条，滚不动） | `Card` 对齐是 `start`，列表容器只写 `vertical-stretch: 1` 拿不到空间 |
| 2 | 启动时代理配置表为空 | 初始加载序列缺 `ProxyListRefresh` |
| 3 | 确认弹窗靠窗口底部时按钮被裁 | `pop-ay` 未按**可视**高度收（`root.height` 是滚动内容高度）；正文未定宽导致 `preferred-height` 低估 |
| 4 | **删除代理后不回滚 rclone**（承诺还原却零写入） | 先 `save_from_cfg` 删绑定，回滚时读不到 `original_override`，被判「不归本程序管」 |
| 5 | 拿不到 `config/providers` 时类型下拉为空、无任何解释 | `unwrap_or(json!({}))` 静默吞错 |
| 6 | 修好认证 + 重新握手后类型仍不更新 | `providers_cache` 无失效点 |

#5 的修法：错误原因入 `providers_err` + 磁盘缓存 `providers_cache.json` 离线兜底 + 内置常见类型兜底，提示里直接给出 `--rc-user/--rc-pass` / `--rc-no-auth` 的做法。
#6 的修法：握手成功时清空两份缓存并预取一次。
