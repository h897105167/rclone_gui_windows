### 1. 按 remote 分配代理（主体功能）

**关键决策（都有实测依据）**：

- **只写 `override.http_proxy` 一个键**。实测 rclone v1.75.4 完全忽略
  `override.socks_proxy`；SOCKS5 靠 URL scheme（`socks5://` / `socks5h://`）区分。
- **协议白名单 4 项**（http/https/socks5/socks5h）。rclone 对未知 scheme
  **不报错**，会静默当 HTTP 代理用 —— 因此校验必须在 RCGUI 侧做完。
- **自己实现百分号编码**，不用 `url` crate：实测 `url` 不编码 `%`
  （会产出 `...%ss` 非法转义），且会把默认端口（80/443）规范化掉。
  按 RFC 3986 的 unreserved 集合编码，覆盖 `@ : / ? # % 空格`，IPv6 自动加方括号。
- **三条安全约束**（这是本功能最容易出致命错误的地方，已用纯函数 + 单测锁定）：
  1. 覆盖前把用户原值记进 `original_override`；多次覆盖**沿用最早的原值**（回滚链不断）
  2. 切回「不代理」→ `Restore(原值)`，**不是**无脑 `Unset`；原本没有该键才 unset
  3. rclone 里的值被别人改过 → 报 `Conflict`，**零写入**

**档案版本 1 → 2**（`crates/profile/src/lib.rs` 的 `SCHEMA_VERSION`）。纯加字段，
v1 档案可读、自动升版，既有挂载/服务/远程不丢（已用真实档案验证）。

### 2. 统一热重载（`crates/app/src/reconcile.rs`）

把「档案=期望」与「rclone 运行态=现状」逐项比对，只重建不一致项：

```
档案（期望）  ──┐
                ├─→ plan（纯函数）──→ execute
运行态（现状） ──┘
```

取代了此前散落在四处的手写逻辑（保存代理 / 切换绑定 / 应用导入 / 连接后重放）。
`plan()` 有 13 个单元测试，锁定「已在监听的 serve 不重启」「`T:` 与 `T:\` 视为同一挂载点」
「未变的代理不重复下发」等行为。

> **关于「一份运行时配置文件」的方案**：用户曾建议用动态配置文件和运行态逐项比对。
> 方向正确，但 **rclone RC 不支持从任意配置文件热加载**（运行中的实例只认启动时的
> `--config`）。因此采用的是同思想的数据版本实现：档案即期望状态，每次现算再 diff。

### 3. 修复的 bug（均有实测或回归测试）

| 问题 | 根因 |
|---|---|
| 删除 remote 后挂载/服务仍在跑 | **顺序错**：先 `config/delete` 再清理，此时 fs 已失效、错误被 `let _ =` 吞掉。实测 rclone 删 remote **不会**自动停 serve。改为先停服务/卸载、最后删远程，且从运行态扫描而非只查档案 |
| 导入时 serve 报 `bind: address already in use` | serve 循环缺「已存在则跳过」检查（挂载循环有，serve 没有） |
| 导入时 serve 报 `missing api_key` | 凭据未随包导出的远程仍尝试启动。**不是 serve 参数问题** —— 实测对缺 api_key 的 teldrive 做任何操作都报这个。改为提前跳过并说明原因 |
| 代理配置/服务名称可重名 | RCGUI 自己的档案数据，rclone 不查重，需自己拦（大小写不敏感、编辑时排除自己） |
| ConfirmPop 按钮点不到、不变手形 | `PopupWindow` **只给了 width 没给 height**，弹出层塌成窄缝，按钮在窗口外 |
| 远程页底部内容被裁 | 卡片限高 + 内部 ScrollView 导致被压扁；改为**整页 ScrollView** |
| 标题栏图标不在左侧 | **`alignment` 是主轴对齐**，写 `center` 会把内容水平居中；垂直居中须用 `cross-axis-alignment` |

## 四、环境与踩坑（必读，多数是这一轮的实际教训）

1. **`%TEMP%` 在本机沙箱下「表面可写、实际写入被拒」**（`os error 5`）。
   诊断日志写到 `%TEMP%` 会完全静默失败。**改用 exe 同目录**。

2. **release 版是 `windows_subsystem = "windows"`，`eprintln!` 全部被丢弃。**
   诊断必须写文件。排查时用 `RCGUI_DEBUG_ICON=1` 打开图标/托盘日志
   （写到 exe 同目录 `rcgui-icon-debug.log`）。

3. **目录的完整性级别会让托盘图标注册失败。**
   `Shell_NotifyIconW` 由高完整性的 explorer.exe 托管，若程序所在目录被打了
   `Low Mandatory Level` 标签，注册被拒 → 现象是「托盘图标不见了」，
   而**管理员身份运行反而正常**（易误判成 ACL/权限问题）。

   ```powershell
   icacls <dir> | Select-String "Mandatory Label"   # 看是不是 Low
   icacls <dir> /setintegritylevel Medium           # 修回普通级别
   ```

   实测对照（同一 exe、同一非提权进程，只换目录）：
   `Low` → `tray: build FAILED: 拒绝访问 (os error 5)`；`Medium` → 正常。
   **注意目录 ACL 里的 DENY 条目不是原因**（移除后仍失败），真正的开关是完整性级别。

4. **托盘图标可能只是被折叠了**（Windows 收进溢出区，需点 `^`）。
   验证是否注册成功**不要靠截图**，查进程窗口类：

   ```powershell
   # 枚举该进程窗口，出现 tray_icon_app 类名即注册成功
   # （它是隐藏窗口，IsWindowVisible = false 属正常）
   ```

5. **验证窗口图标是否真的设上**：查 `WM_GETICON`（`0x7F`），
   返回非 0 句柄才算成功；返回 0 说明 `WM_SETICON` 没执行或没拿到 HWND。

6. **`Start-Process -PassThru` 在本机会阻塞**（且 `-RedirectStandard*` 会因
   `NO_PROXY`/`no_proxy` 字典冲突直接失败）。启动程序请用
   `cmd /c start "" /D <dir> <exe>`。

7. **切勿用 `Get-Content` + `Set-Content -Encoding utf8` 改写源码**。
   PowerShell 5.1 按 GBK 读入、UTF-8 写出，**逐字破坏所有中文注释**。
   改写源码用 `edit`/`write` 工具，或 `[IO.File]::ReadAllText/WriteAllText` + UTF8Encoding($false)。

8. **git commit message 的 BOM 坑**：用 `Out-File -Encoding utf8` 会带 BOM，
   导致提交信息首字符变成 `﻿`。用 `write` 工具生成文件（无 BOM）后
   `git commit -F <file>`，提交前可检查前 3 字节不是 `EF BB BF`。

9. **数据目录 ACL 问题（历史遗留）**：若曾以管理员身份运行，`%APPDATA%\RCGUI`
   的 owner 会是 `BUILTIN\Administrators`，普通权限进程后续写入会报「拒绝访问」。
   代码里已有 `config::ensure_user_can_write_once()`（真实写探测 + 补 Users 权限）
   与 `write_atomic` 的失败重试。**但普通权限进程无法修复 owner 是 Administrators
   的目录** —— 这种情况需要手动 `icacls <dir> /grant "<用户>:(OI)(CI)F" /T` 一次。

10. **PowerShell 变量名大小写不敏感**，`$M` 与 `$m` 是同一个变量。

11. **`icacls` 的退出码不可靠**：带 `/C` 时即使报「拒绝访问」仍返回 0。
    判断成功要看输出里的失败字样，不能只看 `status.success()`。
