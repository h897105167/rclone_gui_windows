# RCGUI 架构

文档状态：**0.3.0 开发版**（2026-11-26）。0.3.0 尚未发布，仓库里最新的正式版本是 v0.2.1。

本文记录当前代码的分层、约束与尚未完成的验收。`已有实现` 不代表已经发布；真实验收范围见 [ACCEPTANCE.md](ACCEPTANCE.md)。

图：[docs/assets/architecture.svg](assets/architecture.svg)（分层示意，和下面第 2 节一致）。

---

## 1. 产品形态

RCGUI 是给 Windows 用的 rclone 图形前端。技术选择只有一条硬约束：**原生 Rust + Slint，不嵌浏览器内核。**

- 界面使用 Slint 原生绘制，进程里没有 WebView2、没有 Electron、没有本地 HTML 界面。
- 本体的内嵌 HTTP 服务是**插件入口**（`/api/health`、`/plugin/{id}/…`），它是给插件用的接口，不是界面。界面上没有任何一页是网页。
- 为什么不用 webview：安装体积、启动时间、以及"用户以为断网就不能用"的困惑。Slint 通过 AccessKit 提供系统可访问性（读屏、键盘遍历）的接口。

### 1.1 rclone 进程归谁管（0.3.0 起的变化）

0.2.x 的规则是「RCGUI 只连一个已经在跑的 RC 端点，绝不启动 rclone」。这条规则在 0.3.0 被替换，原因是它把最常出错的一步（`rclone rcd` 带什么参数、端口占没占、密码在哪）留给了用户。

0.3.0 的规则：

| 模式 | 谁启动进程 | 谁可以结束它 | 默认 |
|---|---|---|---|
| **managed core** | RCGUI 自己拉起受管子进程 | 只有 RCGUI，且只结束**自己拉起的那个 PID** | 是 |
| **external endpoint** | 用户或脚本在外部启动 | 没有人。RCGUI 只连接、只断开连接 | 可选 |

三条不可越界的细则：

1. **只停自己的子进程。** 通过 `attach` 连上的外部端点，在任何路径上都不得调用 `core/quit`，也不得 kill 进程。删除挂载点、停止 serve 是 RC API 上的**运行时操作**，和进程生死不是一回事，这个区别在代码里必须靠类型区分，不能靠注释。
2. **不扫端口、不问邻居。** 只连用户明确选择或由自己启动的端点，目标默认 `127.0.0.1`。发现系统上有个 `rclone.exe` 在跑，不等于有个可用的 RC 服务。
3. **托管进程崩溃后不自动重启**，除非用户在设置里明确打开。默认展示"已停止 + 原因 + 重试按钮"。自动重启会在配置错误时变成死循环，也会掩盖真正的失败。

## 2. 分层

```
┌──────────────────────────────────────────────────────────────┐
│ Shell / UI 层            Slint 视图 + 视图模型 + i18n         │  只渲染快照，不做 IO
├──────────────────────────────────────────────────────────────┤
│ Core Manager 层          托管/外部端点、进程生命周期、端口     │  唯一有权写"核心状态"
├──────────────────────────────────────────────────────────────┤
│ RC Transport 层          HTTP + 鉴权 + 超时 + 错误分类        │  不知道界面，不知道进程
├──────────────────────────────────────────────────────────────┤
│ Plugin Sandbox 层        WASI 宿主 + 能力授权 + kv + 入口     │  崩溃不带走主进程
├──────────────────────────────────────────────────────────────┤
│ Services 层              update / store / backup / sync /     │  后台任务，可被界面取消
│                          diagnostics                          │
└──────────────────────────────────────────────────────────────┘
        ↑ 依赖方向只能向下：UI → Manager → Transport → HTTP
        ↑ Services 依赖 Transport 与 Manager，反过来不行
```

现在的目录映射：

| 层 | 现有 crate / 文件 | 状态 |
|---|---|---|
| Shell / UI | `crates/app`（`main.rs` 里 Slint 视图与视图模型）、`crates/i18n` | 已有 |
| Core Manager | `crates/app/src/core.rs`（`resolve`、`Core`、`StartSpec`、`Running`、`Phase`、`install_from_zip`） | 已有实现，未发布 |
| RC Transport | `crates/rc`（`client.rs`、`handshake.rs`、`conn.rs`、`fetch.rs`、`error.rs`） | 已有 |
| Plugin Sandbox | `crates/plugin`（`package.rs`、`config.rs`、`zip.rs`、`bundle.rs`）+ `crates/app/src/caps.rs` | 已有 |
| Services | `crates/app/src/{maintenance,store,update,backup,sync_tasks,cli,refresh,persist,profiles,conf_io,reconcile}.rs` 与 `crates/profile` | **部分有代码，未发布** |

0.3.0 不要求把目录一次性重排。分层是**依赖规则**，不是文件夹名字。新增代码只要遵守"只能向下依赖"，就不必等重构。

## 3. 各层职责

### 3.1 Shell / UI 层 — `已有`

- 职责：把状态画出来，把用户动作翻译成一条命令交给下层。**不做网络请求，不读写配置，不启停进程。**
- 线程模型：UI 线程只跑 Slint。所有 IO 在 `tokio` 运行时上跑，结果通过通道回到 UI 线程再更新属性。跨线程直接改 Slint 属性是未定义行为，这条在 0.2.x 已经踩过一次（"修非 UI 线程改界面静默失效"）。
- 视图：仪表盘、文件、远程、挂载、服务、传输、插件、设置。视图之间只共享视图模型，不共享可变全局量。
- 多语言：`crates/i18n` 提供 zh/en 两套字符串；插件可以带自己的译文（`params.lang`）。切换语言不重建窗口。
- 状态展示必须区分四种语义：`运行中` / `已保存` / `待应用` / `已断开（数据陈旧）`。断开连接不清空本地数据，只打标记。

### 3.2 Core Manager 层 — `已有实现，未发布`

现在：内核管理在 `crates/app/src/core.rs`。`resolve(custom, exe_dir, data_dir)` 决定用哪个可执行文件——自定义路径优先，其次是 exe 同级与数据目录里较新的那个，最后才查 PATH；`Core` 负责启动、健康检查与唯一一次有序关闭；`install_from_zip()` 从官方包安装内核，`guard_target_dir()` 拒绝把它装到不该装的地方。`crates/rclone/src/proc.rs` 只剩 `attach`（连一个已存在的端点）和 `discover_exe`（找 `rclone.exe`），它带着守卫测试 `crate_has_no_process_spawning`，断言这个 crate 自己不创建进程；托管内核不在那里落地，那个测试也不会因为这次改动被删。

这些代码在 HEAD 里，没有随任何版本发布过。0.3.0 的实现按下面的状态机组织，几条规则是验收时要逐条对照的清单，而不是已经验收过的结论：

```
Stopped ──start()──▶ Starting ──handshake ok──▶ Running(owned)
   ▲                    │                          │
   │                    └──失败──▶ Failed         ├──user stop()──▶ Stopped
   │                                    │          └──进程退出──▶ Failed(原因)
   └────────────────重试────────────────┘

Disconnected ──attach(url)──▶ Attached(external) ──detach()──▶ Disconnected
                                   │
                                   └── 端点不通 ──▶ Disconnected(原因)   ← 不杀进程
```

规则：

- `Running(owned)` 与 `Attached(external)` 是**不同类型**，`stop()` 只对 `owned` 存在。
- 端口：托管模式下由 RCGUI 选一个空闲端口（绑定后立刻释放，或让 rclone 报错再换），把实际端口写进状态，界面显示真实值。端口冲突要作为独立错误上报，不并进"启动失败"。
- 凭据：托管模式的 RC 用户名/密码每次启动随机生成，只在运行期使用，不持久化到配置、日志或导出文件。外部端点的用户凭据另按配置与导出规则处理。
- 退出清理：进程句柄与 Job Object 绑定，主进程异常退出时子进程随之结束，不留孤儿 `rclone.exe`。
- Windows 上不弹控制台窗口（`CREATE_NO_WINDOW`），但 stderr 要捕获到日志环形缓冲，供"诊断"导出。

### 3.3 RC Transport 层 — `已有`

- 职责：把 RC API 变成 Rust 的 async 函数。`crates/rc/src/client.rs` 负责请求与鉴权，`handshake.rs` 负责连上之后读版本与能力，`error.rs` 负责把 HTTP/JSON 错误分成**可展示**的类型。
- 连接握手要先读 `core/version` 与配置路径，再决定后续调什么。旧版本缺 API 要明确说"这个版本没有该接口"，不要静默降级成"操作成功但没生效"。
- 超时分层：连接 3 s、普通查询 10 s、长操作（复制、删除目录）不设统一上限但必须可取消。
- 错误分类必须是枚举，不是字符串拼接：`未连接` / `鉴权失败` / `端点不可达` / `接口不存在` / `被拒（参数或权限）` / `超时` / `后端错误`。界面上的文案由分类决定，这样"挂载失败"永远不会覆盖"没装 WinFsp"。
- 不允许重叠的同类请求；旧响应不许覆盖新状态（带请求序号，小的丢弃）。

### 3.4 Plugin Sandbox 层 — `已有`

- 职责：加载 `wasm32-wasip1` 插件，只给它被声明的能力。
- 能力是**白名单**：`kv` `ui` `fs` `http` `proc` `net` `rclone` `env`。`fs.` / `proc.` / `http.` 属于危险能力，插件声明了就在安装页明确列出，不隐藏。
- 隔离边界：插件崩溃、死循环、返回垃圾数据，都只能影响它自己那次调用。宿主必须能超时并杀死该调用。
- 存储：`kv` 由宿主实现（`crates/app/src/kv.rs` 的 `KvStore`），键空间按插件 id 分隔。
- 入口：声明 `http_entry: true` 的插件可以在 `127.0.0.1` 上被 HTTP 调用，路由是 `GET /api/health`、`ANY /plugin/{id}`、`ANY /plugin/{id}/{*rest}`（旧路径 `ANY /api/plugin/{id}/{*rest}` 保留）。这个服务默认只监听回环地址，不加鉴权——所以文档必须把"本机任何程序都能调用"说清楚。
- 版本契约见 [PLUGIN.md](PLUGIN.md)：协议版本 1；能力只增不减；废弃操作至少保留两个次版本；宿主必须跳过不认识的控件类型；升级时比较 `config.json.version`，内置包更新才覆盖用户目录副本，`kv` 数据保留。

### 3.5 Services 层 — `部分有代码，未发布`

五个服务，边界按"用户能单独关掉/单独诊断"来切。表格里每一项都标了今天的真实状态，**没写完的不许在 README 里当已发布功能写**。

| 服务 | 做什么 | 现在 |
|---|---|---|
| **update** | 检查本体新版本、下载、校验、替换 | 已有实现，未发布：便携版退出后由独立脚本按计划替换，失败回滚；安装版启动校验后的安装程序。真实跨版本升级仍需发布候选验收 |
| **store** | 拉插件索引 `index.json`、列出可装插件、按 sha256 安装 | 部分：`crates/app/src/store.rs` 负责拉索引、比版本、下载校验与解压安装，`maintenance.rs` 管刷新与状态文案，界面在插件页的「商店」标签；索引页与索引 `docs/store/` 已在本仓库 |
| **backup** | 配置、插件清单与设置的导出/导入、WebDAV 备份 | 已有实现，未发布：`crates/profile` 管格式与合并，`conf_io.rs` 管预览应用，`backup.rs` 管有限大小、禁止重定向的 PUT/GET；不包含插件包体 |
| **sync** | 本地目录与远程目录之间的定时文件同步 | 已有实现，未发布：`sync_tasks.rs` 管方向、周期、单任务占用、内核代次与取消。默认本地到远程、每 6 小时、只复制不删除；不是 profile 多端点同步 |
| **diagnostics** | 收集版本、能力、连接状态、日志尾部，产出可粘贴的报告 | 部分：`crates/app/src/cli.rs` 的 `--diagnostics --json` 在 HEAD 里；契约见 [CLI.md](CLI.md) |

Services 的共同约束：

- 界面显示进行状态与错误。同类更新、商店和备份操作受并发闸门保护；文件同步作业支持取消。其余网络操作以超时结束，不能把禁用按钮描述成已经支持取消。
- rclone 请求通过 RC Transport；商店、更新与备份使用各模块受约束的 HTTP 客户端，配置超时、响应大小和重定向策略，不能把备份认证头转发给第三方地址。
- 下载到盘的东西先写临时文件，校验 sha256 后再原子替换；校验失败保留旧文件。

## 4. 跨层契约

### 4.1 并发

- **单一写者**：核心连接状态只有 Core Manager 能改；UI 只读快照。Transport 层不持有"当前是否已连接"的判断。
- **单飞（single-flight）**：同类刷新不并发。窗口从最小化恢复、切换页面、用户点刷新的三条触发路径要合并成一次请求。
- **前台才轮询**：窗口不可见或最小化到托盘时停止轮询，恢复时立刻拉一次并更新"最后刷新时间"。
- **取消优先**：用户离开页面、切换远程、断开连接时，在途请求标记作废，结果丢弃而不是延后应用。
- **不阻塞 UI**：任何超过一帧的工作都进后台；同步 IO（读配置、算 hash）也要搬走。

### 4.2 缓存

| 缓存对象 | 位置 | 失效条件 | 注意 |
|---|---|---|---|
| RC 状态快照（远程/挂载/服务） | 内存 | 显式刷新、重连、窗口复原 | 断开后**保留**并标"陈旧"，不清空 |
| 插件包 | `crates/app/assets/plugins`（构建期）/ `%APPDATA%\RCGUI\plugins`（运行期） | `.fetched.json` 里 tag 或 sha256 变化 | 替换用临时目录 + 原子改名 |
| 插件索引（store） | 当前维护状态的内存快照 | 用户刷新 | 不是持久离线商店；安装包仍按清单 sha256 校验 |
| 图标/缩略图 | 内存 LRU | 容量上限 | 不落盘，避免把远程内容写进本地缓存目录 |
| 语言包 | 进程内 | 切换语言 | 插件自带译文随包，不联网取 |

原则：**缓存永远不是真源**。任何"因为缓存里有，所以认为远程存在"的判断都是 bug。

### 4.3 凭据

- RC 密码、OAuth token、云服务密钥：不写普通日志，不进崩溃报告，不进截图，导出时明确提示"包含敏感数据"。
- 托管模式的 RC 密码由 RCGUI 随机生成，仅运行期使用。外部端点密码与 WebDAV 密码保存在本地配置中；`rclone obscure` 是混淆不是加密。
- 界面里展示密码一律掩码；"显示"是一次显式点击，且不写入剪贴板历史（能控则控，不能控就在文档说明）。
- 导出 `rcgui.conf` 时凭据字段的处理必须显式选择，默认剥离，并在预览里逐项列出被剥离的字段。

### 4.4 状态真源

- **运行时真源是 rclone**：有什么 remote、有没有在挂载、serve 起没起，以 RC 返回为准。
- **期望状态真源是 RCGUI**：用户想要的挂载/服务参数（含 `mount/listmounts` 不返回的那些选项）由 RCGUI 自己持久化。
- 二者永不互相推导。`mount/listmounts` 的结果不足以重建一个挂载配置，这是已知事实，不是待修 bug。
- 界面同时展示"现在跑的"和"保存的"，差异显式标出，不自动"纠正"任何一边。

### 4.5 可访问性

目标是让界面**可以被键盘完整操作、被读屏念出来、被放大镜看清**，而不是"通过了某个检查"。

- 键盘：所有可交互元素可 Tab 到达，顺序符合视觉顺序；`Esc` 关闭对话框；`Enter` 触发主操作；列表支持方向键；不设键盘陷阱。
- 命名：每个控件有可读名称与角色。图标按钮必须有文本名（可见或仅供辅助技术读取）。
- 视觉：正文对比度 ≥ 4.5:1，字号可放大到 200% 不破版；不靠颜色单独传达状态（用图标/文字补充）。
- 焦点可见：默认焦点环不许被样式抹掉；模态对话框打开时焦点进入并困在内部，关闭后回到触发控件。
- 动效：尊重系统"减少动画"设置。
- **诚实条款**：`--export-accessibility-tree` 导出的是 RCGUI **自己声明**的界面结构（静态树），它是"我们打算暴露什么"的快照，**不等于** Windows UIA 在运行时的真实树。真实 UIA 验证必须用 Inspect.exe / Accessibility Insights 在真机上人工核对。文档和 CLI 帮助里都要写这句话，不许把静态树当成无障碍验收证据。

### 4.6 测试契约

三层，各有明确边界，不许互相冒充：

1. **工作区测试**（`cargo test --workspace`）：解析、映射、错误分类、配置迁移、hash 校验，以及隔离的进程和文件系统集成测试。部分测试启动临时子进程或回环 HTTP 服务；不得读取用户配置、连接真实云端或改动用户进程。
2. **契约/守护测试**：把"不许做的事"写成会失败的测试。现存例子：`crates/rclone/src/proc.rs` 里 `crate_has_no_process_spawning` 用 `include_str!` 检查实现里没有 `Command::new` 等字样。这条守护跟着 `crates/rclone` 的边界走——这个 crate 只 attach、只找 exe，所以它继续检查"本 crate 不 spawn"是正确的约束，托管内核在 `crates/app/src/core.rs` 里实现，不共用这条测试。哪天有人往 `crates/rclone` 里塞进程启动，这条测试仍然该失败。
3. **人工验收**（不进 CI）：真实 rclone 版本握手、真实挂载（需要 WinFsp）、真实 Telegram/teldrive 登录、读屏软件核对。

禁止事项：为了让流水线变绿而删测试、把断言改成 `assert!(true)`、用 `println!` 输出当测试结果、把"脚本跑通了"说成"功能验证了"。检查脚本只证明脚本本身能跑，不证明应用功能正确。

### 4.7 发布契约

- 版本号唯一来源是工作区 `Cargo.toml` 的 `[workspace.package] version`，六个成员 crate 全部 `version.workspace = true`；运行时通过 `env!("CARGO_PKG_VERSION")` 取（`crates/app/src/caps.rs` 已经在发给插件的能力表里带 `gui_version`）。
- 资产命名固定：`RCGUI-<version>-windows-x64-setup.exe`、`RCGUI-<version>-windows-x64-portable.zip`，配套 `SHA256SUMS.txt`。命名规则和校验方式见 [RELEASE.md](RELEASE.md)。
- 可重现：发布包里的 rclone 内核来自固定 tag 的官方资产并按 sha256 校验；插件来自 `plugins/manifest.json` 锁定版本并校验；构建脚本不允许"用本机上碰到的那个 exe"。
- 不得发布的东西：开发数据、token、绝对路径、未校验的二进制、测试用的临时 release。

## 5. 现在 vs 目标

| 能力 | 0.2.1（已发布） | 0.3.0（开发中） |

## 6. 迭代边界

1. 托管内核生命周期留在 `app/src/core.rs`；`crates/rclone` 继续只连接与发现可执行文件，保留其不创建进程的守护测试。
2. 新远程类型来自当前内核的 `config/providers`；插件只能声明现有后端的预设，不能凭元数据给官方内核增加原生后端。没有插件时不向新建列表注入 K-Vault；旧配置仍可编辑。
3. 大列表、插件面板与 WASM 缓存可在轻量模式释放；用户草稿、后台作业和受管内核独立保存。恢复窗口时先退出轻量模式，再重建视图。
4. Slint 只启用软件渲染、Windows 窗口与无障碍所需特性；Wasmtime 保留运行现有 WASI 插件必需的功能。调整依赖必须同时验证真实插件包与发布构建，不能只比较依赖数量。
5. 新功能通过 PR、完整工作区测试和相应集成验收后合并。发布前单独验证安装、卸载保留数据、跨版本更新和真实服务；未测范围写入验收记录。

## 7. 术语

- **core**：rclone 进程本身。
- **managed core**：由 RCGUI 拉起的 core，生命周期归 RCGUI。
- **external endpoint**：用户自己启动的 core 暴露的 RC 地址，RCGUI 只连接。
- **RC API**：rclone 的远程控制 HTTP 接口（例如 `/core/version`），需要 `rclone rcd` 或 `--rc` 才可用。
- **WASI**：WebAssembly 的系统接口子集。插件是 `wasm32-wasip1` 模块，只能通过宿主给的能力与外界交互。
- **能力（capability）**：插件声明、用户可见、宿主可拒的权限项。
- **投影**：把 rclone 返回的运行时状态映射成界面模型的过程，只读、单向。
